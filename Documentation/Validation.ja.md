# Editorでの機能検証記録

2026-10-28にUnity 6000.5.8f1、Built-in、Windows Editorで戦闘動作を確認しました。以下は、自動テストと別途実行した戦闘で実際に検証した範囲です。

[プロジェクトのREADMEに戻る](../README.ja.md)

## 自動テスト

戦闘ルールはEditModeテスト、シーンでの戦闘進行と操作はPlayModeテストで確認しました。どちらも失敗やスキップなしで合格しています。

| 区分 | 結果 | 主な確認内容 |
|---|---|---|
| EditMode `BattleContractTests` | **25/25件合格** | 入力と配置、攻撃ルール、同時命中、敵探索、アニメーションデータ、実際の物理APIによる移動・照会・解放 |
| PlayMode `BattleSessionTests` | **5/5件合格** | 戦闘終了、停止と1ステップ実行、エンジン切り替えと再開始、ボタンとUI、大規模戦闘後の資源解放 |

各テストの名前、結果、所要時間は[test-results.json](test-results.json)に、実装は[Testsフォルダー](../Assets/PhysicsComparisonLab/Tests/)にあります。

PlayModeでは両エンジンで1:1、1:2、25:25、100:100、250:250の戦闘を動かし、決着がついて死亡アニメーションまで終わることを確認しました。停止中に位置とステップ数が変わらず、1ステップボタンで正確に一度だけ進むことも検査しています。エンジンの切り替えと再開始を10回繰り返した後には、body・world・表示オブジェクトやボタンのイベントハンドラーが増えていないか確認しました。

入力と画面配置も検査しました。+10/+50/+100/Maxボタンは各陣営2,500体の上限に従い、不正な入力は拒否されました。右パネルは戦場や入力欄を隠さず、SoldierとOrcの生存数も実際の戦闘状態と一致していました。

大規模な自動テストは、**両エンジンで1,500対1,500を各120ステップ**実行したものです。テスト名に`Maximum`が含まれていますが、現在の上限である2,500対2,500を終了まで検証するテストではありません。

## 実際の実行画面

EditorのGame Viewから、1920×1080のPNGを5枚撮影しました。画像は編集しておらず、撮影時の状態とファイルハッシュは[screenshots.json](screenshots.json)に記録しています。

| 画面 | 確認した状態 |
|---|---|
| 準備 | 25:25、0ステップ |
| 従来のPhysics2D | 250:250で開始、120ステップで停止、生存231/229 |
| PhysicsCore2D | 250:250で開始、120ステップで停止、生存229/228 |
| Core大規模 | 2,500:2,500で開始、120ステップで停止、生存2,437/2,435、body・shapeともに4,876個 |
| Core終了 | 25:25を実時間の1倍速で実行、280ステップでSoldier勝利、生存4/0 |

大規模画面の表示数が5,000なのは、死亡アニメーション中のユニットも含むためです。物理bodyは生存ユニットと境界4個だけが残るので、表示数とは異なります。停止中や終了後のFPSは、戦闘中の性能を示すものではありません。

別途行った[Editor CPU測定](Benchmarks/README.ja.md)は、160回すべて完了しました。両エンジンの5,000体の実験では死亡を無効にし、各実行で120ステップ準備してから600ステップを収集しました。生存数の維持と資源解放は確認していますが、死亡のある5,000体の通常戦闘を終了まで検証した結果ではありません。

## 検証終了時の状態と範囲

検証終了時には、コンパイルとConsoleのエラー・警告はいずれも0件でした。Playを終了し、シーンに未保存の変更がないことを確認しています。デフォルトCore worldの1個を除く物理オブジェクトと、一時的な測定オブジェクトも片付け、従来の物理実行モードは`FixedUpdate`に戻しました。詳しくは[最終状態の記録](final-state.json)にあります。

当時の撮影・測定作業では、ランタイムC#、シーン、アセット、パッケージは変更していません。作業前後で`Assets`・`Packages`・`ProjectSettings`にあった既存190ファイルのハッシュが一致しています。撮影中の一時画像も、文書フォルダーに移してから元の場所を整理しました。

新しいPlayerビルドや独立Playerの性能、他プラットフォーム、ネットワーク上の決定論、worker・substep設定による違い、メモリ・GC・GPUは検証していません。この記録の結果は、上記のEditor実行範囲に限られます。
