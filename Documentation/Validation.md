# Editor 기능 검증 기록

2026-10-28에 Unity 6000.5.8f1, Built-in, Windows Editor 환경에서 전투 동작을 확인했습니다. 아래는 자동 테스트와 별도 실행에서 실제로 확인한 범위입니다.

## 자동 테스트

전투 규칙은 EditMode 테스트로, 씬에서의 전투 진행과 조작은 PlayMode 테스트로 확인했습니다. 두 테스트 모두 실패하거나 생략한 항목 없이 통과했습니다.

| 구분 | 결과 | 주요 내용 |
|---|---|---|
| EditMode `BattleContractTests` | **25/25 통과** | 입력과 배치, 공격 규칙, 동시 명중, 적 탐색, 애니메이션 데이터, 실제 물리 API의 이동·조회·해제 |
| PlayMode `BattleSessionTests` | **5/5 통과** | 전투 종료, 정지와 한 스텝 진행, 엔진 전환과 재시작, 버튼과 UI, 대규모 전투 후 자원 해제 |

테스트별 이름과 결과, 소요시간은 [test-results.json](test-results.json)에 있으며 구현은 [Tests 폴더](../Assets/PhysicsComparisonLab/Tests/)에서 볼 수 있습니다.

PlayMode에서는 두 엔진으로 1:1, 1:2, 25:25, 100:100, 250:250 전투를 실행해 승패가 나고 사망 표시까지 끝나는지 확인했습니다. 정지 중에는 위치와 스텝이 그대로 유지되고, 한 스텝 버튼을 누르면 정확히 한 번만 진행되는지도 검사했습니다. 엔진 전환과 재시작을 10회 반복한 뒤에는 body·world·표시 객체가 중복되거나 버튼 이벤트가 늘지 않는지 확인했습니다.

입력과 화면도 함께 검사했습니다. +10/+50/+100/Max 버튼은 진영별 상한 2,500에 맞게 작동하고 잘못된 입력은 거부됐습니다. 우측 패널은 전장과 입력 영역을 가리지 않았으며, Soldier와 Orc의 생존 수도 실제 전투 상태와 일치했습니다.

대규모 자동 테스트는 **1,500 대 1,500을 두 엔진에서 각각 120스텝** 실행한 결과입니다. 테스트 이름에 `Maximum`이 들어 있지만 현재 상한인 2,500 대 2,500을 끝까지 검증한 테스트는 아닙니다.

## 실제 실행 화면

Editor Game View에서 촬영한 1920×1080 PNG 5장을 수록했습니다. 이미지는 편집하지 않았으며 촬영 상태와 파일 해시는 [screenshots.json](screenshots.json)에 기록했습니다.

| 화면 | 확인한 상태 |
|---|---|
| 준비 | 25:25, 0스텝 |
| 기존 Physics2D | 250:250 시작, 120스텝에서 정지, 생존 231/229 |
| PhysicsCore2D | 250:250 시작, 120스텝에서 정지, 생존 229/228 |
| Core 대규모 | 2,500:2,500 시작, 120스텝에서 정지, 생존 2,437/2,435, body·shape 각각 4,876 |
| Core 종료 | 25:25를 실제 1배속으로 실행, 280스텝에 Soldier 승리, 생존 4/0 |

대규모 화면에서 표시 수가 5,000인 것은 사망 애니메이션 중인 유닛도 포함하기 때문입니다. 물리 body는 생존 유닛과 경계 4개만 남으므로 표시 수와 다릅니다. 정지하거나 종료한 화면에 나온 FPS는 전투 중 성능을 나타내지 않습니다.

별도의 [Editor CPU 측정](Benchmarks/README.md)은 160회 모두 완료했습니다. 양쪽 엔진의 5,000유닛 실험에서는 사망을 끄고 매 실행마다 120스텝을 준비한 다음 600스텝을 수집했으며, 생존 수 유지와 자원 해제를 확인했습니다. 이 결과를 사망이 있는 5,000유닛 일반 전투의 종료 검증으로 해석해서는 안 됩니다.

## 검증을 마친 상태와 범위

검증을 마쳤을 때 컴파일과 Console 모두 오류·경고가 0개였습니다. Play를 종료하고 씬에 저장하지 않은 변경이 없는지 확인했으며, 기본 Core world 1개를 제외한 물리 객체와 임시 측정 객체도 정리했습니다. 기존 물리 실행 모드는 `FixedUpdate`로 복구했습니다. 자세한 상태는 [최종 확인 기록](final-state.json)에 있습니다.

당시 촬영과 측정 작업에서는 런타임 C#, 씬, 에셋, 패키지를 변경하지 않았습니다. 작업 전후 `Assets`·`Packages`·`ProjectSettings`의 기존 190개 파일 해시가 같았고, 촬영 중 생긴 임시 이미지도 문서 폴더로 옮긴 뒤 정리했습니다.

새 Player 빌드나 독립 Player의 성능, 다른 플랫폼과 네트워크 결정론, worker·substep 설정별 차이, 메모리·GC·GPU는 검증하지 않았습니다. 이 문서의 결과는 위에 적은 Editor 실행 범위에 한정됩니다.
